RETURNS OF DOING AN ACTION

1. observation (also known as the state)
Type: Typically a NumPy array or image (in the case of Atari games, it’s often an RGB image representing the current screen).
Meaning: The current state of the environment after taking the action. For Atari games like Montezuma's Revenge, the observation represents the visual state of the game, typically in the form of an image (pixels).
Usage: This is the input that your agent will use to decide the next action (in a DQN, for example, it would be fed into the network to predict Q-values).

2. reward
Type: Float
Meaning: The immediate reward received after performing the action. For Atari games like Montezuma's Revenge, this might be points the player earns for making progress in the game.
Usage: This reward is crucial for training your RL agent. The goal of your agent is to maximize the cumulative reward over time.

3. done
Type: Boolean (True or False)
Meaning: Indicates whether the episode has finished. When done is True, the episode (or game) is over, and the environment needs to be reset before you can take more actions. This could happen because the player lost all lives, reached a game-over screen, or completed the level.
Usage: When done is True, you typically reset the environment using env.reset() to start a new episode.

4. truncated
Type: Boolean (True or False)
Meaning: Indicates whether the episode was truncated because it exceeded a predefined limit (like a time or step limit) rather than reaching a natural terminal state like game over. truncated is used to differentiate between natural termination and forced truncation.
Usage: Similar to done, but specifically tells you if the environment stopped due to a limit. You may need to handle truncations differently depending on your setup.

5. info
Type: Dictionary
Meaning: This provides additional diagnostic information about the environment. It is optional and can include a variety of useful data such as game-specific details like the player's score, number of lives, or the position of certain objects in the game.
Usage: The content of info depends on the environment. For example, in Montezuma's Revenge, it could include information like the number of keys collected, the current room number, or internal metrics useful for debugging or learning.
